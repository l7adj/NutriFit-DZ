# تشغيل الخادم وربط النسخة المتصلة

## الحالة

يتضمن المستودع الآن API مبنياً بـ Express وPostgreSQL، ومخططات قاعدة بيانات، ومصادقة JWT، وصلاحيات خادمية، ومسارات للعميل والإدارة والمطبخ والتوصيل. لكن إضافة الكود لا تعني أن الخدمة أصبحت منشورة أو متصلة بقاعدة بيانات حقيقية. يلزم إعداد بيئة استضافة وقاعدة بيانات وأسرار تشغيل قبل تفعيل الوضع المتصل.

## المتطلبات

- Node.js 22 أو أحدث.
- PostgreSQL 15 أو أحدث مع اتصال TLS في بيئة الإنتاج.
- نطاق HTTPS للخدمة.
- قيمة سرية عشوائية لـ JWT لا تقل عن 32 حرفاً؛ لا تضعها في Git أو في متغيرات VITE_*.
- نسخ احتياطي تلقائي لقاعدة البيانات.

## الإعداد

1. أنشئ قاعدة PostgreSQL مستقلة للإنتاج.
2. انسخ ملف .env.example إلى .env على الخادم فقط.
3. عيّن:
   - DATABASE_URL: رابط PostgreSQL.
   - DATABASE_SSL=true: تفعيل TLS لقاعدة البيانات.
   - JWT_SECRET: سر عشوائي طويل وفريد.
   - APP_ORIGIN: نطاق الواجهة، ويمكن أن يكون أكثر من نطاق مفصولاً بفواصل.
   - VITE_API_ENABLED=true: يُقرأ وقت بناء الواجهة لتفعيل تسجيل الدخول والاتصال بالخادم.
   - VITE_API_BASE_URL: اتركه فارغاً إذا كانت الواجهة والـ API على النطاق نفسه.
4. ثبّت الحزم وشغّل الترحيلات والبناء:
   ~~~bash
   npm install
   npm run db:migrate
   npm run lint
   npm test
   npm run build
   npm start
   ~~~
5. وجّه HTTPS إلى الخادم. يخدم Express ملفات dist ومسارات /api من الأصل نفسه.

## إنشاء حساب الإدارة الأول

التسجيل العام ينشئ حساب customer فقط. لا توجد واجهة عامة تمنح صلاحية الإدارة.

1. أنشئ حساباً عادياً من شاشة التسجيل.
2. شغّل أمر الترقية من بيئة الخادم الموثوقة بعد التحقق من البريد المقصود:

   ~~~bash
   BOOTSTRAP_ADMIN_EMAIL=admin@example.com npm run admin:promote
   ~~~

3. سجّل الخروج ثم الدخول مجدداً حتى يصدر JWT بالدور الجديد.
4. أنشئ حسابات العاملين بالطريقة نفسها ثم غيّر الدور إلى kitchen أو delivery حسب الحاجة.

لا تمنح دور admin لأي حساب لا يملكه المشغّل فعلياً.

## تهيئة التشغيل قبل استقبال العملاء

1. أضف مكونات غذائية من لوحة الإدارة، مع القيم لكل 100غ أو 100مل، ومصدر السجل، وحالة الوزن، ومسببات الحساسية.
2. راجع كل سجل ثم اعتمده؛ يبقى المكوّن غير نشط حتى تفعيله صراحةً.
3. أنشئ الوصفات من مكونات نشطة وموثقة، ثم راجعها وفعّلها.
4. أنشئ مناطق الخدمة بأحياء وساعات حقيقية، ثم فعّل المناطق المعتمدة فقط.
5. اضبط رسوم الخدمة وموعد الإغلاق والسعة اليومية. السعة 0 تعني إيقاف استقبال الطلبات.
6. أنشئ حسابات المطبخ والتوصيل، ثم اسند الطلبات المؤكدة إلى حساب توصيل محدد.

## مسارات API الأساسية

| المسار | الصلاحية | الغرض |
|---|---|---|
| POST /api/auth/register | عام | إنشاء حساب عميل |
| POST /api/auth/login | عام | تسجيل الدخول |
| GET /api/auth/me | مسجل | استعادة الحساب |
| GET /api/foods و GET /api/dishes | عام | العناصر النشطة والموثقة فقط |
| GET /api/zones | عام | مناطق الخدمة النشطة فقط |
| GET/PUT /api/profile | عميل | الملف الغذائي والحساسيات |
| POST/GET /api/orders | عميل | إنشاء الطلبات وعرض سجل العميل |
| GET/POST/PATCH /api/admin/* | إدارة | إدارة المكونات والوصفات والمناطق والإعدادات والطلبات |
| GET /api/kitchen/orders | إدارة/مطبخ | قائمة التحضير |
| PATCH /api/kitchen/orders/:id/stage | إدارة/مطبخ/موصل مسند | الانتقال بين مراحل الإنتاج والتسليم |
| GET /api/delivery/orders | موصل مسند | الطلبات المسندة إلى حسابه |

## ضوابط مهمة

- السعر والماكروز وحالة الطلب تُعاد حسابها على الخادم؛ لا يعتمد الخادم على السعر الذي يرسله المتصفح.
- لا يقبل الخادم مكوّناً غير نشط أو غير موثق أو بلا حالة وزن ومصدر.
- يُعاد فحص الحساسية والملف الصحي والسعة ومنطقة الخدمة عند إنشاء الطلب.
- لا تُقبل الطلبات حتى تُضبط السعة اليومية إلى قيمة أكبر من صفر.
- لا يمكن لحساب التوصيل رؤية طلبات موصل آخر أو تحديث مراحل المطبخ.
- انتقالات المطبخ والتوصيل متسلسلة؛ لا يجوز تخطي مرحلة من حسابات العاملين.
- جميع عمليات إنشاء الطلبات وتغيير المراحل المهمة تُسجل في audit_log.
- JWT قصير العمر (12 ساعة) ويُحفظ في تخزين المتصفح في النسخة الحالية؛ استخدم HTTPS وسياسة CSP صارمة وراجع مخاطر XSS قبل الإطلاق.

## ما لا يزال يحتاج مزوداً أو مراجعة خارجية

- لا يوجد تكامل دفع إلكتروني؛ طريقة الدفع الحالية في قاعدة البيانات نقداً عند الاستلام وحالتها معلقة.
- لا يوجد تكامل خرائط أو شركة توصيل؛ الإسناد والتحديثات تشغيل يدوي داخل لوحة الفريق.
- لا يوجد تحقق بريد إلكتروني أو استعادة كلمة مرور أو MFA.
- لا توجد خدمة تخزين صور سحابية للصور الشخصية.
- لم تُملأ قاعدة الأغذية ببيانات إنتاج موثقة؛ لوحة الإدارة تبدأ فارغة في قاعدة البيانات الجديدة.
- لا توجد بعد مراجعة أمنية مستقلة أو اختبار اختراق أو اعتماد من مختص تغذية وسلامة غذاء.

**لا تفعّل VITE_API_ENABLED على خدمة عامة قبل إعداد قاعدة البيانات، وترقية حساب الإدارة، وإضافة مكونات ومناطق معتمدة، وتجربة طلب كامل من العميل إلى التسليم.**
