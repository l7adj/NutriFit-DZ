# نموذج التشغيل المستهدف — NutriFit DZ

> هذه وثيقة تصميم تشغيلي. البنود أدناه تصف السلوك المطلوب عند اكتمال الخادم والمطبخ، ولا تعني أن هذه العمليات متصلة حالياً. قيم الساعة والمنطقة والسعر في بيانات المعاينة أمثلة تحتاج اعتماداً تجارياً.

## 1. رحلة العميل

### أ. فتح الملف والتحقق من السلامة
- إنشاء حساب موثق قبل حفظ بيانات صحية.
- موافقة صريحة على معالجة قياسات الجسم والبيانات الصحية الضرورية.
- بوابة السلامة تسأل عن العمر والحالات التي تتطلب إشرافاً طبياً والحساسيات وعدم التحمل.
- الحالات عالية الخطورة لا تحصل على خطة آلية؛ تعرض سبب الإيقاف وخيار مراجعة مختص.
- الحساسيات قيد منع صارم وليست مجرد تفضيل يمكن تجاوزه.

### ب. الحساب الغذائي
- تخزين مدخلات العميل مع وحدة القياس ومصدرها وتاريخ تحديثها.
- حساب RMR بمعادلة موثقة؛ لا تُستخدم كتلة LBM إلا إذا كان القياس موثقاً.
- اختيار PAL من نطاق واضح مع توثيق القيمة الافتراضية والاختيار اليدوي.
- حفظ نسخة المحرك العلمي وإصداره ومعادلاته وافتراضاته مع كل نتيجة.
- كل نتيجة تحمل تصنيفاً: F معادلة، R نطاق مرجعي، O اختيار تشغيلي، C افتراض معايرة.
- لا يُفرض حد أدنى أو حد أقصى صامت يغيّر الطاقة المستهدفة. أي تعارض ينتج عنه تنبيه أو حجب مع تفسير.

### ج. تصميم الوجبات
- يعرض النظام الاحتياج اليومي والكمية المتبقية من الطاقة والبروتين والكربوهيدرات والدهون.
- يختار العميل عدد الوجبات، ثم يوزع الأطباق والمكونات على كل وجبة.
- كل مكوّن له حالة وزن صريحة: نيء، مطبوخ، أو كما يباع؛ ولا تُخلط القيم بين الحالات.
- تظهر الكمية بالغرام، والماكروز، والسعر، والحساسيات، ومصدر بيانات الغذاء.
- يمنع النظام إضافة عنصر غير متوفر أو يحتوي على مسببات حساسية مسجلة.
- التعديلات على الكمية تعيد حساب الماكروز والسعر فوراً، مع عرض أثرها على اليوم كاملاً.

### د. مراجعة الطلب
قبل الإرسال، يعرض ملخصاً غير قابل للالتباس:
- تاريخ التحضير/التسليم المتوقع والمنطقة والنافذة الزمنية.
- عدد الوجبات ومكوناتها وأوزانها.
- إجمالي السعر مع فصل المكونات والمناولة والخدمة والتوصيل.
- ملاحظات العميل والحساسيات.
- سياسة الإلغاء وآخر وقت لقبول الطلب.
- حالة الطلب: مسودة، مرسل، قيد المراجعة، مؤكد، قيد التحضير، جاهز، خرج للتوصيل، تم التسليم، أو ملغى.

لا يُخصم مخزون ولا تُرسل دفعة للمطبخ قبل تأكيد الخادم للطلب. يجب أن يكون الإرسال idempotent حتى لا ينتج عن النقر المتكرر طلبان.

## 2. دورة الطلب والتحضير

1. **استلام الطلب:** الخادم يتحقق من الحساب، الحساسية، الأسعار الحالية، توافر المكونات، السعة، والموعد.
2. **مراجعة الإدارة:** الطلبات غير الاعتيادية أو التي تتجاوز الطاقة أو تحتوي على بيانات ناقصة تتوقف للمراجعة البشرية.
3. **تجميع دفعة المطبخ:** تجميع كميات المكونات حسب وصفات الطلبات المؤكدة فقط، مع حفظ نسخة الوصفة والسعر وقت الطلب.
4. **قائمة التحضير:** ترتيب حسب وقت التحضير، نوع الطبخ، معدات المطبخ، ومتطلبات الفصل لمنع التلوث التبادلي.
5. **الوزن والتعبئة:** تسجيل الوزن الفعلي لكل مكوّن أو حصة، مع سماحية تشغيلية معتمدة ومعلنة.
6. **مراقبة الجودة:** فحص الهوية، المكونات، مسببات الحساسية، درجة الحرارة، الإغلاق، والملصق قبل التسليم.
7. **التسليم للسائق:** إنشاء manifest للطلبات حسب المنطقة، تسجيل وقت الاستلام، وإثبات التسليم.
8. **إغلاق اليوم:** مطابقة الطلبات والمخزون والهدر والإلغاءات، ثم إعداد تقرير تشغيلي.

## 3. الأدوار والصلاحيات

| الدور | الصلاحيات المستهدفة |
|---|---|
| العميل | ملفه، خطته، وجباته، طلباته، ومدفوعاته فقط |
| الإدارة | العملاء والكتالوج والتسعير والسعة والطلبات والتقارير |
| المطبخ | الطلبات المؤكدة وقوائم التحضير والوزن والجودة فقط |
| التوصيل | الطلبات المسندة إليه ومعلومات التسليم الضرورية فقط |

يجب فرض هذه الصلاحيات في API وقاعدة البيانات، وليس عبر إخفاء أزرار الواجهة. لا يحق للمطبخ تغيير ملف العميل الصحي أو السعر الأصلي للطلب.

## 4. سجلات يجب حفظها

- ملف العميل وموافقات الخصوصية.
- نسخة الحساب الغذائي: المدخلات، المحرك، الإصدار، المصادر، والنتائج.
- مصدر كل قيمة غذائية، حالة الطعام، الجزء المأكول، وعامل مردود الطهي.
- نسخة ثابتة من الوصفة والسعر عند إنشاء الطلب.
- سجل حالات الطلب مع المستخدم والوقت والسبب.
- حركة المخزون: استلام، حجز، استهلاك، هدر، وتسوية.
- سجل دفعات التحضير وفحوص الجودة والتسليم.

## 5. شروط قبول النسخة التشغيلية

لا تُعلن الخدمة جاهزة حتى تتحقق جميع النقاط التالية:
- مصادقة خادمية وصلاحيات منفصلة واختبار منع الوصول الأفقي.
- قاعدة بيانات مشتركة ونسخ احتياطي وسجل تدقيق.
- اختبارات حسابات غذائية واختبارات تكامل للطلبات والمخزون.
- بيانات غذائية موثقة لكل صنف مستخدم تجارياً، مع النيء/المطبوخ والمردود.
- مراجعة مختص تغذية وسلامة غذاء للإجراءات والملصقات.
- اعتماد مناطق التوصيل والأسعار والموعد النهائي والطاقة الفعلية.
- اختبار دورة طلب كاملة من العميل إلى المطبخ ثم السائق وإثبات التسليم.

## 6. ما هو منفذ الآن وما ليس منفذاً

**منفذ في الواجهة التجريبية:** إدخال بيانات، حاسبة أولية، اختيار أصناف وأوزان، حساب تكلفة تقديري، حساسية أساسية، حفظ محلي، وجورنال وزن.

**غير منفذ بعد:** حسابات مستخدمين حقيقية، خادم، قاعدة بيانات مشتركة، تحقق مخزون حقيقي، إدارة دفعات المطبخ، تتبع وزن فعلي، الدفع، تكامل التوصيل، إشعارات، سجل تدقيق، ومزامنة الأجهزة.
