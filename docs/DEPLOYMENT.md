# تشغيل NutriFit DZ المتصل

## الحالة

المشروع يحتوي على واجهة عميل عربية، وخادم Express، وطبقة PostgreSQL، ومسارات منفصلة للعميل والإدارة والمطبخ والتوصيل. **وجود هذه الملفات لا يعني أن الخدمة مستضافة أو أن قاعدة بيانات حقيقية مرتبطة.** لا تُفعّل وضع API في الواجهة قبل تجهيز الخادم وقاعدة البيانات.

## المتطلبات

- Node.js 22
- PostgreSQL 14 أو أحدث
- عنوان HTTPS للواجهة والخادم في بيئة الإنتاج
- قاعدة بيانات ونسخة احتياطية دورية
- إعداد أسرار التشغيل في منصة الاستضافة، وليس داخل Git

## الإعداد

1. أنشئ قاعدة PostgreSQL مستقلة.
2. انسخ `.env.example` إلى `.env` محلياً، ثم أدخل `DATABASE_URL` و`JWT_SECRET` عشوائياً بطول 32 حرفاً على الأقل.
3. شغّل `npm install`.
4. شغّل `npm run db:migrate` لتطبيق ملفات SQL بالترتيب.
5. شغّل `npm run build` ثم `npm start`.
6. اختبر `GET /api/health` وتأكد من أن حالة قاعدة البيانات `connected`.
7. أنشئ حساباً عادياً من واجهة التسجيل، ثم امنحه دور الإدارة من بيئة الخادم فقط:

```bash
BOOTSTRAP_ADMIN_EMAIL=admin@example.com npm run admin:promote
```

هذا أمر إداري يدوي لمرة واحدة. لا توجد واجهة عامة لترقية الحسابات. أنشئ حسابات المطبخ والتوصيل من أدوات إدارة قاعدة البيانات بعد التحقق من هوية أصحابها، مع تعيين الدور إلى `kitchen` أو `delivery`.

## تفعيل واجهة API

اضبط متغيرات بناء الواجهة:

- `VITE_API_ENABLED=true`
- `VITE_API_BASE_URL=` اتركه فارغاً إذا كانت الواجهة والخادم على نفس النطاق؛ وإلا ضع عنوان API الكامل.
- `APP_ORIGIN` في الخادم يحدد النطاقات المسموح لها بطلبات CORS.

أعد بناء الواجهة بعد تغيير متغيرات `VITE_*`، لأنها تُضمّن وقت البناء. لا تضع `DATABASE_URL` أو `JWT_SECRET` في أي متغير يبدأ بـ `VITE_`.

## بوابات الإطلاق التي لم تُحسم بعد

- لا توجد بوابة دفع إلكتروني أو تأكيد دفع؛ الحالة الافتراضية للدفع نقداً عند الاستلام و`pending`.
- لم تُختبر رسائل SMS أو البريد أو الإشعارات.
- بيانات الطعام والأسعار لا تصبح موثوقة بمجرد إدخالها؛ يلزم توثيق المصدر والوزن والتحقق من القيم واعتمادها إدارياً.
- لا تفعّل مناطق التوصيل أو الطاقة اليومية قبل التأكد من القدرة الفعلية، ساعات الخدمة، التكاليف، ومسارات التوصيل.
- يلزم اختبار قبول فعلي للعميل والمطبخ والسائق على بيئة تجريبية قبل استقبال أموال أو بيانات صحية حقيقية.
- التوكن الحالي يُحفظ في تخزين المتصفح؛ قبل الإطلاق التجاري العام يُفضّل نقله إلى جلسة Cookie آمنة `HttpOnly` مع حماية CSRF، وتفعيل تحقق البريد ومراجعة أمنية مستقلة.

## الفحوصات الآلية

تعمل GitHub Actions على تنفيذ:
- `npm run lint`
- `npm test`
- `npm run build`

نجاح هذه الفحوصات لا يغني عن اختبار قاعدة بيانات فعلية، أو مراجعة أمنية، أو اختبار سير العمل في المطبخ والتوصيل.
